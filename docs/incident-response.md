# 障害対応手順書（v0.1.0）

## 1. 重大度定義

| 重大度 | 定義 | 例 |
| --- | --- | --- |
| P1（重大） | システム全体が利用不能 | API 全滅 / DB 接続不能 |
| P2（高） | 主要機能が利用不能 | グラフ表示不能 / 取込失敗 |
| P3（中） | 一部機能・表示異常 | CSV出力不具合 / アラート誤検出 |
| P4（低） | 軽微・改善要望 | 文言・スタイル不備 |

## 2. 初動（P1/P2）

1. ヘルスチェックで切り分け
   - `live` NG → Worker 設定・デプロイ状態
   - `ready` NG → Neon 接続・DB状態
   - Web NG → アセットデプロイ状態
2. `wrangler tail cci-api-production` でエラーログ確認
3. Neon ダッシュボードで接続・容量・メンテナンス状態確認
4. 影響範囲を GitHub Issue に記録

## 3. ロールバック

Worker はバージョン管理されているため、過去デプロイへ戻せる:

```bash
# 過去デプロイ一覧
cd apps/api && npx wrangler deployments list
# 特定バージョンへロールバック
npx wrangler rollback --id <version-id>
```

Web も同様（`apps/web` ディレクトリで実行）。

**ロールバック判断基準**: P1 発生時は追加変更より復旧を優先し、原因調査は復旧後に行う。

## 4. DB データ復旧

- Neon のポイントインタイムリカバリ（履歴保持 1 日デフォルト）
- 破壊的マイグレーションは承認なしに実行しない
- バックアップ手順は [docs/backup-restore.md](backup-restore.md) を参照

## 5. 事後処理

- 原因・対応・再発防止を Issue に記録
- リリースノートへ追記
- 監視アラート条件の見直し
