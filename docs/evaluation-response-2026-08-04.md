## 2. 検証結果

### 2.1 総合評価（68/100・「積算支援基盤であって積算中核システムではない」）

**妥当。** 本システムに工事案件管理・歩掛展開・諸経費計算・積算書出力は存在せず、
現時点で「正式な積算システム」ではない。README・要件定義書でも「参考情報」「対象外」
とされているが、明示的な位置付け表記が弱かったため、本対応で強化した。

### 2.3 特に重要だった指摘と対応

1. **提供元の誤記載（経済産業省 → 国土交通省）**

   事実誤認ではなく実在する誤記載だった。国土交通省が毎月公表する建設資材モニター調査であり、
   リポジトリの README / データ取得手順書 / migration 003 / 管理画面プリセットに「経済産業省」と
   記載されていた。**本対応で全箇所を修正し、migration 005 で既存DBも補正した。**

2. **動向評価値（1〜5段階）を実単価・指数と同じ系列として扱う危険**

   評価の指摘どおり、`ESTAT_MATERIAL_SUPPLY` の全国平均値（価格動向・今回調査）は円建ての
   実価格ではなく、モニターによる1〜5段階の動向評価値。本対応で `data_kind = trend_assessment` /
   `estimate_usable = false`（参考のみ）として DB・API・画面・Excel出力で区別するようにした。

3. **「積算システム」という呼称・位置付けの曖昧さ**

   README と要件定義書に「正式な積算システムではない。建設コスト・市況分析基盤（積算判断支援）」
   であることを明記した。

## 5. 推奨する導入方針（評価提案への同意）

評価の3段階導入に同意する。

1. **Phase 1: 市況分析基盤** — ✅ 実装済み。積算・営業・経営層の価格動向共有
2. **Phase 2: 案件影響分析** — ✅ 実装済み（`/projects`・シミュレーションAPI）。案件データの投入を開始
3. **Phase 3: 積算連携** — 既存の正式積算システム／Excelと接続し、単価候補・根拠・改定差分を受け渡し

既存の積算システムを置き換えるのではなく、「不足している市況情報と案件影響分析を補完する基盤」として
導入するのが安全かつ効果的である。
